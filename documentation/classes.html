Classes & Objects

Classes are nominal types with single inheritance. Constructor parameters live in the class header and become checked fields — no setmetatable ceremony.

Declaring a class

Constructor parameters are declared in the class header and are automatically promoted to fields. Required params are declared non-null; optional ones take ?. Classes nest and localize freely — the compiler assigns each a unique flat runtime name, so same-named local classes coexist.

player.sol content_copy 
class Player(name : string, id : number)
    function say(self : Player, msg : string)
        print(self.name .. " says: " .. msg)
    end

    function id_value(self : Player) : number
        return self.id
    end
end

Creating instances

A class is callable: constructing is a direct call, checked for arity and argument types. Method calls use Lua's colon sugar, which injects the receiver as self.

instances.sol content_copy 
local p : Player = Player("bob", 42)
p:say("hello")              -- bob says: hello

local n : number = p.id_value()
print(n)                    -- 42

Inheritance

extends declares single inheritance; super-constructor arguments go in the header. Overriding an inherited method requires the override keyword, and self narrows to the subclass. Inside an override, super.m(self, ...) reaches the parent.

admin.sol content_copy 
class Admin(role : string) extends Player("admin", 0)
    override function say(self : Admin, msg : string)
        print("[" .. self.role .. "] " .. msg)
    end
end

local a : Admin = Admin("root")
a:say("override works")

local x : Player = a   -- ok: Admin is a Player
x:say("dynamic")       -- dispatches to Admin.say

Abstract classes

An abstract class cannot be instantiated and may declare abstract methods — signatures without bodies that concrete subclasses must implement (with override).

abstract.sol content_copy 
abstract class Animal
    abstract function speak(self : Animal) : string
end

class Dog extends Animal("woof")
    override function speak(self : Dog) : string
        return "woof"
    end
end

final classes

The final prefix seals a class: it cannot be extended. Since no subclass can exist, every method call on a final-typed receiver compiles to a direct flat call — monomorphic by construction, even when unrelated classes share the method name. final abstract is rejected as contradictory.

final.sol content_copy 
final class Token(kind : string, value : string)
    function render(self : Token) : string
        return self.kind .. ":" .. self.value
    end
end

-- class Sub extends Token("x", "y") end  -- error: Token is final

Member-level final methods are planned — class-level sealing ships today.

data and object

data declares a plain record: constructor parameters become fields, and that is all. object declares a singleton with methods — its self needs no type annotation.

data.sol content_copy 
data Pair(a : number, b : number) end

local p = Pair(1, 2)
print(p.a + p.b) -- 3

object Registry
    function put(self, k : string, v : number)
        print("stored " .. k)
    end
end

Registry:put("key", 1)

Interfaces

An interface declares a contract: required method signatures, optionally constructor mandates in its header. Classes satisfy them with implements (several at once). Interfaces may also provide default method bodies. An interface itself cannot be instantiated.

shapes.sol content_copy 
interface Shape(name : string)
    function area(self : Shape) : number
end

class Circle(x : number, name : string) implements Shape
    function area(self : Circle) : number
        return 3
    end
end

local s : Shape = Circle(1, "unit") -- ok: Circle is a Shape
