LANGUAGE — TOOLING

Tooling

One compiler script drives everything: it picks the dialect by file extension, prints loud tiered errors, and emits plain Lua 5.1.

The compiler

shell content_copy 
lua main.lua <input.sol | input.lua> [options]
    -o, --output <file>   write generated Lua (default: stdout)
    --run                 compile and execute in-process
    -v, --verbose         dump tokens and AST
    -h, --help

Imports resolve relative to the compiler script, not the caller's working directory.

Two dialects, one parser

The extension picks the dialect: .sol files are soleil — the full grammar, parsed and type-checked — while .lua files are plain Lua: parsed and emitted, never type-checked. This lets existing Lua pass through the same pipeline untouched.

Loud, tiered errors

The checker aborts on the first violation — there is no error recovery and no unchecked mode. Errors are tiered and carry line numbers: Parse Error at line N: ... from the front end, type error at line N: ... from the checker. All tiers exit non-zero. Nesting is bounded too: 100 nested functions at parse, 1500 statement levels in the checker and emitter — loud errors, never a C-stack crash.

#!INCOMPLETE markers

A file may carry a #!INCOMPLETE marker (as a shebang or an inline --#!INCOMPLETE comment). The checker refuses to fully check a marked file unless lenient mode is requested through the API (options.allow_incomplete). This is how in-progress stdlib declaration files stay honest.

libstring.hds content_copy 
#!INCOMPLETE: 3 of 12 functions could not be typed
-- libstring.hds — declarations for Lua's string library

function string.sub(s : string, i : number, j : number?) : string end
function string.len(s : string) : number end

Test suites

Everything in the v1 core is locked behind the suites in tests/:

  • parser — 128 grammar probes (valid must parse, malformed must error)
  • checker — 192 semantic contracts (valid must check, invalid must fail with the right message)
  • integration — 19 whole-program scripts through the front end
  • corpus — 24 files of the Lua 5.1 test suite through parse → emit → loadstring
  • round-trip — 39 files: emit → re-parse → normalized AST equivalence
  • battery — 59,198 recursive combinations: nesting × field typing × payload shapes, plus adversarial expect-error contracts
