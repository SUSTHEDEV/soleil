Metatables & Coroutines

Soleil classes deliberately do not use metatable dispatch — but raw metatables remain available for interop, and coroutines remain plain Lua.

Flat dispatch, not __index chains

The compiler is ahead-of-time and explicit, and targets plain Lua 5.1 with types fully erased. A class becomes __ClassName_method(self, ...) functions plus a __ClassName_new(params) constructor that builds the table, runs the base constructor first, sets fields, then installs methods — base methods copied first, derived last, so overrides win. No metatable __index traversal ever happens at call time.

Dispatch is census-gated: a call compiles to a direct flat call when the checker can prove the method is monomorphic across the program; polymorphic sites — overridden methods and interface-typed receivers — dispatch through the instance-carried method.

Consequence: methods are not monkey-patchable at runtime — dispatch is fixed at compile time. That is intentional under the explicit philosophy.

Raw metatables for interop

setmetatable is typed in the standard library, so pure-Lua object code still checks. Reach for raw metatables when integrating with libraries that expect them — not for new data modelling (use classes).

meta.sol content_copy 
local account = {}
account.__index = account

function account.new(balance : number)
    return setmetatable({ balance = balance }, account)
end

local acct = account.new(100)
print(acct.balance)

Coroutines

Coroutines remain plain Lua: create one, then resume and yield to hand control back and forth.

coroutines.sol content_copy 
local co = coroutine.create(function()
    for i = 1, 3 do
        coroutine.yield(i)
    end
end)

print(coroutine.resume(co)) -- true   1
print(coroutine.resume(co)) -- true   2
print(coroutine.status(co)) -- suspended

When to reach for coroutines

  • Iterators that produce values lazily
  • Schedulers and simple job queues
  • Breaking long loops into resumable steps
