Type System

Soleil is strict by description: there is no implicit escape from the type system. Types are checked at compile time and erased — the output is plain Lua 5.1.

Value types

Every Soleil type maps 1:1 to a Lua 5.1 value:

  • boolean, number, string
  • nil — a first-class singleton type
  • table[V] / table[K, V] / table[any] — the table family
  • class / interface / data names — nominal types
primitives.sol content_copy 
local name : string = "Sol"
local mass : number = 1.989e30
local alive : boolean = true
local nothing : nil = nil

Nullability and unions

Unions are the one composite type mechanism. Nullability is sugar, and T? is the canonical spelling — x : T | nil is not grammar. A nullable union puts the ? on its last member: A | B?. The nil literal has type nil, so it is assignable to any union containing nil — but never to a plain T. Nullability is idempotent: (T?)? is just T?.

unions.sol content_copy 
local x : number?         = nil     -- ok
local y : number          = nil     -- error: nil is not a number
local u : string | number = 1       -- ok
local n : nil             = nil     -- ok

Tables

Tables come in three canonical forms. A bare table annotation is a parse error — pick a form. Empty literals must be annotated. Reads are always nullable: t[k] has type V? even when V is not — discharge with a nil-guard, ?:, or !!.

  • table[V] — arrays (number-keyed), iterate with ipairs, length with #
  • table[K, V] — maps, iterate with pairs
  • table[any] — the heterogeneous escape hatch
tables.sol content_copy 
local xs : table[number]       = { 1, 2, 3 }
local ages : table[string, number] = { alice = 100 }
local junk : table[any]        = { 1, "two", true }

local first : number? = xs[1]  -- reads are nullable

Literals are element-checked: a positional literal infers the union of its elements, so { Circle(1), Square(1) } types as table[number, Circle | Square] and assigns cleanly to table[Circle | Square] — while { 1, "x" } is rejected against table[number]. And per Lua's prefixexp rule, constructors are never callable or indexable directly: write ({1, 2})[1].

any — table-only

any is legal only inside table brackets: table[any], table[K, any], table[any, V], and union members within those brackets (table[number | any]). Everywhere else — parameters, returns, locals, class fields, interface members — bare any is a compile error.

The split is deliberate: dynamic signatures are typed unknown (see below); dynamic collections are typed with any in their brackets. Inside its legal home, any is assignable in both directions — the one trusted channel, and opt-in only: nothing produces it implicitly. It also cannot be used as a class name.

any.sol content_copy 
local xs  : table[any]         = { 1, "two", true }  -- ok
local map : table[any, number] = {}                  -- ok

-- local bad : any = 1          -- error: bare any outside a table

unknown

unknown is the type of values whose shape the compiler cannot know. The only producer is varargs data: select(n, ...) spreads unknowns, and a bare ... flows as unknown into any positions. Anything flows in; nothing flows back out except to itself, to any, or through a checkpoint. Arithmetic, concatenation, indexing, and calls on unknown are all errors.

unknown.sol content_copy 
local data : unknown = 5
data = "now a string"        -- anything flows in

local flexible : any = data  -- out to any: ok
local label : string = tostring(data)  -- through a checkpoint

local n : number = data      -- error: cannot initialize

What produces what:

  • annotated function call — exactly its declared return types
  • rets-less function call — nil
  • select("#", ...) — number; select(n, ...) — n-1 unknowns
  • tonumber(x) — number?; tostring(x) — string; type(x) — string

Nothing produces unknown or any implicitly. any is written by the programmer or it does not exist.
